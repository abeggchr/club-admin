# Income Statement layout is a checked-in YAML file

The Income Statement (Erfolgsrechnung) layout lives as a YAML file in the repository and is read at startup, like the Chart of Accounts (ADR 0001). The top-level key is `Erfolgsrechnung`, with the sections `Ertrag` and `Aufwand`; each section contains groups, and each group maps German labels to a single account number or a range written `from-to`. Key order is preserved and drives the A./B. section letters, the I./II./III. group numerals and the line order of the report.

The layout is validated against the Chart of Accounts at startup (ADR 0001): a single Account that is missing from the plan, an Account mapped more than once (including through ranges), a reversed range, a range matching no Account, or an Account in the wrong section (Expense under Ertrag, Income under Aufwand) refuses startup with a German message naming the offending entry, like the Chart of Accounts consistency check. Inactive Accounts remain mappable and a range may contain numbers that are not in the chart, so retiring an Account or skipping numbers never breaks the layout.

We chose this over an editable in-app layout because the club reports the statement in a fixed structure, the change is rare, and a YAML diff in review is exactly the right granularity for a treasurer to understand. A failed health check on Railway keeps the previous deployment live, so an inconsistent edit never reaches production. The cost is that a layout change needs a deploy, and a broken file takes the whole app down until it is fixed.
